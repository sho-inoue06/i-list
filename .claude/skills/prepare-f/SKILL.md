# prepare-f

版：2026-11-11

禁止と境界は AGENTS.md（「セッションごとの境界」の準備の行と「### 準備」）に従う。このファイルは手順だけを持ち、AGENTS.md の境界を緩めない。矛盾したら AGENTS.md を優先して停止する。

## 目的

明示的に起動されたときだけ、Notionの指定Fページ1件を読み取り、Fのbranchを用意して、repo内の次の2ファイルを実装用に準備する。

- docs/current-task.md
- docs/current-run.md

2ファイルの生成の後、事前点検（Codex、読み取り専用）を自分で起動する。NGのうち答えが1つに決まるもの（甲）だけを直して再点検し、決まらないもの（乙）は選択肢にして祥に聞く。

事前点検がOKになり、祥が明示承認した後に、2ファイルだけを1回commitして凍結する。

## 起動条件

- 指定されたNotion FページのURLが必要
- 実装AI、レビューAIが指定されていない場合は推測せず停止する

## 手順の全体

1. Fページを読み、F識別子を抽出する
2. branchを用意する（新規作成、またはやり直しモード）
3. 2ファイルを空欄テンプレートから生成する
4. 事前点検を自動で起動する（1つのFで最大2回）
5. NGを1件ずつ甲・乙に仕分ける（乙があれば、直す前に停止して祥に聞く）
6. 甲の修正と祥の乙の回答をFページへ反映し、2ファイルを作り直して4へ戻る
7. 報告して停止する
8. 祥の明示承認の後、凍結commitを1回行う

## 1. Fページの読み取り

- 指定されたFページを読む。ここでは読むだけで、書かない（Fページへ書くのは 6 だけ）
- コメント、議論、他ページ、バックログ全体を読まない
- F識別子（例：F-24）を抽出する。branch名は `feat/f-xx`（F識別子を小文字にしたもの）とする
- F識別子が抽出できない場合は停止する

## 2. branchの用意

### 2-1. 同名branchの有無

- `git rev-parse --verify --quiet refs/heads/<branch>` で同名のローカルbranchの有無を確認する
- 無ければ 2-2 へ、あれば 2-3 へ進む

### 2-2. 新規作成

1. `git status --porcelain` で未コミット差分（未追跡ファイルを含む）が無いことを確認する。1件でもあれば停止する
2. `git fetch origin`
3. `refs/remotes/origin/<branch>` があれば（同名branchが既にある）停止する
4. `git switch -c <branch> origin/main`
5. 作ったbranch上の docs/current-task.md・docs/current-run.md が origin/main の内容と同一（前のFの凍結仕様）なら、そのファイルを空欄テンプレートへ戻す。ファイルが無ければ空欄テンプレートで新規作成する

### 2-3. やり直しモード

`git fetch origin` の後、次の3つをすべて満たすときだけ続行する。1つでも満たさなければ停止する。

- 現在そのbranchにいる（`git branch --show-current` が `<branch>`）
- origin/main より先のcommitが0件（`git rev-list --count origin/main..HEAD` が 0）
- 未コミット差分が docs/current-task.md と docs/current-run.md だけ（`git status --porcelain` に、この2ファイル以外のパスが1件も無い。stage済み・未追跡も含めて見る。2ファイルの差分が片方だけ・0件の場合も、他のパスが無ければ満たすとみなす）

満たした場合は、2ファイルを空欄テンプレートへ戻してから 3 へ進む。branchは作らない。

## 3. 2ファイルの生成

### 生成前の確認

- 2-2・2-3の後、2ファイルが下の空欄テンプレートと一致しない場合は上書きせず停止する

### current-task.mdへ入れる内容

- F番号または成果識別子
- 目的
- 対象範囲
- 番号付き完成条件
- 出てはいけないもの
- やらないこと
- 必須検証
- 実装に必要な未決事項

### current-task.mdへ入れない内容

- 会社実データ
- 個人情報
- 秘密情報
- 認証情報
- Notion URL
- 実装に不要な人名、組織名、案件名
- 他のFやバックログ全体
- 優先順位
- 長い判断履歴
- branch、HEAD、push状況
- 実装結果、レビュー結果、過去の作業履歴

機密情報や会社固有情報を抽象化できない場合は、ファイルを書かず停止して確認を求める。
Notionの内容をそのまま外部AIへ渡さず、実行に必要な情報だけを抽出する。

### current-run.mdへ入れる内容

- Task：F識別子（docs/current-task.md）
- Implementer：指定された実装AI
- Reviewer：指定されたレビューAI
- Reviewer model・Reviewer effort：レビューAIの設定ファイル（Codexなら docs/codex-review.md、Claude Codeなら docs/claude-review.md）の値を写す。値が条件つきで1つに決まらない場合は停止して質問する
- Procedure：docs/procedures/implement.md のまま変えない
- `## Immutable` はテンプレートの固定文のまま変えない

実装AI、レビューAI、モデル、effortを推測しない。

### 生成と反映

- current-task.mdとcurrent-run.mdは一時ファイルとして生成してから内容を検査する
- 機密情報が混入していないことを確認し、検査に失敗した場合は既存ファイルを変更しない
- 検査成功後にだけ対象ファイルへ反映する

## 空欄テンプレート

### docs/current-task.md

```markdown
# Current Task

凍結された今回の実行仕様（WHAT）。進捗や現在地を書き込まない。
実装AI・レビューAIはこのファイルを変更しない。

## 成果識別子

## 目的

## 対象範囲

## 完成条件

## 出てはいけないもの

## やらないこと

## 必須検証

## 実装に必要な未決事項
```

### docs/current-run.md

```markdown
# Current Run

実装開始前に凍結する実行契約。進行状態のログではない。
実装AI・レビューAIはこのファイルを変更しない。

- Task:
- Implementer:
- Reviewer:
- Reviewer model:
- Reviewer effort:
- Procedure: docs/procedures/implement.md

## Immutable

- docs/current-task.md を変更しない
- Preparation modeでの初回生成または空欄テンプレートの充填は許可する
- 充填後はcurrent-run.mdを変更しない。ただし凍結commit前に限り、準備セッションのやり直しモード（.claude/skills/prepare-f/SKILL.md の 2-3）で空欄テンプレートへ戻して再生成できる
- Implementation modeとReview modeでは変更禁止
- workflow、実装AI、レビューAI、停止点、回数を自己判断で変更しない
- 仕様変更が必要なら実装を停止し、Notion更新後に/prepare-fを再実行する
- Notion を読み書きしない
- push、権限変更、仕様変更は別承認
```

空欄テンプレートとの一致は、上の本文とファイル全体が一致することで判定する。current-run.md は Task・Implementer・Reviewer・Reviewer model・Reviewer effort が空欄で、Procedure と Immutable が上のとおりであることをいう。

## 4. 事前点検の自動起動

3 の生成と反映が終わったら、祥の指示を待たずに事前点検を起動する。

### 回数

- 自動の点検は、1つのFで最大2回。この `/prepare-f` の起動の中で、点検の起動（失敗した起動も含む）を数える
- 既に2回起動していたら、3回目は起動しない
- 祥が手でDefine（Fページ）を直して `/prepare-f` を再実行したときは、回数を数え直す
- 2-3 のやり直しモードで入り、祥がDefineを直したと伝えていないときは、前の起動の回数が分からないので、点検を起動する前に祥へ確認する（直していないなら数え直さない）

### 起動

- docs/codex-review.md の「起動コマンド」をそのまま使い、`codex exec` を起動する。`-s read-only`・`--ephemeral` を付け、モデル（`-m`）と推論強度（`-c model_reasoning_effort`）は docs/codex-review.md の値を毎回明示する。値を変えない
- Codex 以外のAI（Claude Code など）を起動しない。read-only 以外では起動しない
- 依頼文は次の固定の1文だけにする。1字も足さない

```
AGENTS.md と docs/procedures/precheck.md に従って、docs/current-task.md を事前点検して。
```

- 前回の点検結果、直した内容、Notionの内容（Fページの本文・「決めたこと」・祥の回答）を、依頼文にも引数にも渡さない。2回目も同じ1文で起動する
- 依頼文の一時ファイルはrepoの外に置き（`mktemp`）、起動後に消す。点検の出力をrepo内のファイルへ保存しない

```bash
PROMPT_FILE="$(mktemp)"
printf '%s\n' 'AGENTS.md と docs/procedures/precheck.md に従って、docs/current-task.md を事前点検して。' > "$PROMPT_FILE"
codex exec --ephemeral -s read-only -C "$(git rev-parse --show-toplevel)" \
  -m <docs/codex-review.md のモデル> -c 'model_reasoning_effort="<docs/codex-review.md の推論強度>"' - < "$PROMPT_FILE"
rm -f "$PROMPT_FILE"
```

### 結果の扱い

- 点検の出力は、報告に使うためそのまま（要約・書き換えなしで）控える
- 起動後に `git status --porcelain` を見て、2ファイル以外のパスが増えていれば停止して報告する
- 「判定：OK」なら 7 へ進む
- 「判定：NG」で1回目なら 5 へ進む
- 「判定：NG」で2回目なら、仕分けも修正もせず 7 の「2回目もNGのとき」で停止する
- 起動に失敗した、または判定が読み取れない場合は、起動し直さずに停止して、出力をそのまま報告する

## 5. NGの仕分け

1回目のNGを、1件ずつ甲か乙に分ける。

### 甲

次の3つをすべて満たすものだけを甲とする。

- 既存の条件の文言を直すだけで解消する（条件番号を増やさない・消さない・本数を変えない）
- 合わせる先が、repoの現物（ファイル:行）、または同じFページの「決めたこと」に書かれた決定である
- 答えが1つに決まる

合わせる先は、点検の出力を信じず、自分で確かめる。確かめられなければ乙とする。

- repoの現物に合わせるとき：そのファイル:行を自分で開いて確かめる
- 「決めたこと」の決定に合わせるとき：1 で読んだFページの「決めたこと」の該当行を確かめる（repoに実装がまだ無くてもよい）

### 乙

- 甲でないものは、すべて乙
- 迷ったら乙
- 観点0（分割）は、常に乙
- 条件番号を増やす・消す・本数を変える修正は、乙

### 乙があるとき

甲を直す前に停止し、乙を1件ずつ次の形で祥に聞く。祥がスマホから番号だけで答えられるように書く。

```
乙1
- 条件番号：
- 何が決まらないか：
- 選択肢（2〜3個）：
  1. <選択肢>（影響：<選ぶとどうなるか>）
  2. <選択肢>（影響：<選ぶとどうなるか>）
  3. <選択肢>（影響：<選ぶとどうなるか>）
- 推奨：<番号>（理由：<理由>）
```

最後に「回答は『乙1=2、乙2=1』のように番号だけでよい」と添える。

- 推奨は書いてよいが、祥の回答が来るまで、乙をFページにも2ファイルにも反映しない。乙を自分で埋めて点検へ回さない
- 祥の回答で文言が1つに決まらない場合は、推測で補わずにもう一度聞く
- 祥が「Defineへ戻す」と答えた場合は、何も直さずに停止する
- 祥の回答が来たら、甲とあわせて 6 へ進む

乙が無いとき（すべて甲）は、そのまま 6 へ進む。

## 6. 甲の修正・再生成・再点検

Fページへ書くのはこの節だけで、書けるのは指定Fページの次の3か所だけとする。

1. 条件の文言：完成条件・出てはいけないもの・やらないこと・必須検証のうち、該当する条件の文言だけを直す。甲は 5 で確かめた合わせ先に合わせる。乙は祥の回答をそのまま反映する（言い換えない・足さない）
2. 「決めたこと」：1件につき1行を足す。既存の行は変えない
   - 甲：`YYYY-MM-DD 事前点検n回目NG：<条件番号>を<前>→<後>（根拠：ファイル:行）（準備のAI）`。合わせ先が「決めたこと」の決定のときは、根拠に「決めたこと」の該当行（日付と書き出し）を書く
   - 乙：`YYYY-MM-DD 事前点検n回目NG：<条件番号>を<前>→<後>（祥）`
3. 定義済み日：その日の日付に上書きする

- 指定Fページ以外のページ、指定Fページの状態・経緯の節・その他のプロパティ・上の3か所以外の本文には書かない。ページ全体を置き換える書き方をせず、該当箇所だけを置き換える
- 書いた後にFページを読み直し、変わったのが上の3か所だけであることを確かめる。違っていれば、それ以上書かずに停止して報告する

その後、次の順で作り直す。

1. 指定Fページを読み直す（1 と同じ範囲）
2. 2-3 のやり直しモードで、2ファイルを空欄テンプレートへ戻す（2-3 の3つの条件を満たさなければ停止する）
3. 3 で2ファイルを生成し直す
4. 4 へ戻る（2回目の点検）

2回目の点検がNGのときは、この節を行わない。

## 7. 報告して停止

1行目に「読んだ手順：.claude/skills/prepare-f/SKILL.md（版：<版>）」を書き、次を報告して停止する。

1. 指定されたFページを読めたか
2. 抽出したF識別子
3. branch名と、新規作成かやり直しモードか
4. 実装AI、レビューAI、モデル、effort
5. current-task.mdとcurrent-run.mdを作成したか
6. 除外・抽象化した情報の種類
7. 機密情報を含めていないことの確認
8. git status
9. 凍結commitの案（対象2ファイル、コミットメッセージ `docs: freeze F-xx spec`、pushしないこと）
10. 点検の回数と、各回の判定
11. 甲の前後表（条件番号・前・後・根拠ファイル:行。合わせ先が「決めたこと」のときはその該当行）。無ければ「無し」
12. 乙と祥の回答。無ければ「無し」
13. 指定Fページの「決めたこと」にある「AIが置いた細部（祥未確認）」の一覧。無ければ「無し」

### 2回目もNGのとき

- 何も直さずに停止する（Fページ・2ファイルとも、2回目の点検を受けた状態のまま）
- 上の1〜8と10〜13に加えて、2回分の点検結果をそのまま（要約・書き換えなしで）載せる
- 9（凍結commitの案）は出さず、代わりに「Define用チャットへ戻す」と書く
- 凍結commitへ進まない

## 8. 凍結commit

次をすべて満たすときだけ、1回だけ行う。1つでも満たさなければcommitせず停止する。

- 事前点検の最後の判定がOKで、祥が凍結commitを明示承認した
- 7の報告後に2ファイルの内容が変わっていない（変わっていたら再報告して承認を取り直す）
- このbranchに凍結commitがまだ無い（origin/main より先のcommitが0件）

手順：

1. `git add -- docs/current-task.md docs/current-run.md`
2. `git diff --cached --name-only` が上の2ファイルだけであることを確認する。他のパスがあれば停止する
3. `git commit` を1回行う
4. pushしない。branch、HEAD、git statusを報告して終了する
