# i-list（移植中の骨格・ダミー専用）

自動車型式の適合必要法規と認証取得実績（認可書）を管理する帳票アプリの骨格。

**現状はダミーデータ専用・業務利用未検証です。** 実車情報・実日程・実認可番号・会社の機微情報は含みません。

## 前提

- Node.js（`node:sqlite` を使うため、比較的新しいバージョンが必要。動作確認は Node v24 系）
- npm

`node:sqlite` は実験的機能です。利用しているNodeバージョンで有効かどうかは `node -e "require('node:sqlite')"` 等で事前に確認してください。

## 導入・起動

```bash
npm ci          # 初回。lockfile通りに依存をインストール
npm run dev     # 画面(Vite)とAPIサーバ(SQLite保存)を同時起動
```

ターミナルに出るURL（`http://127.0.0.1:5173`）をブラウザで開く。

止めるときは `Ctrl + C`。

データは編集すると自動でAPIサーバ（`server/index.js`）経由でSQLiteに保存されます（画面右上に保存状態表示）。保存先は `data/ilist.db`（`.gitignore`対象、リポジトリには含まれません）。

### 本番モード（ビルドして1プロセスで動かす）

```bash
npm run build   # dist/ に静的ファイルが出る
npm run server  # http://127.0.0.1:3001 だけで画面もAPIも動く
```

APIサーバ・Vite開発サーバともに **127.0.0.1（ローカルホスト）限定**で待ち受けます。LAN公開やトンネル経由の外部公開は行っていません（意図的にそうしています）。

## データ形・API

- データ形: `{ schemaVersion: 2, runs, regs, cert }`。`cert` は認証実績で、型式ラン × 法規行ごとに `{ runKey, rid, ck, planned }` を1件持つ配列（F-22）
  - 版番号の無い旧形式（`cert` が `{ 型式: { 法規ID: 認可番号 } }`）は、読み込み時にその型式のすべての型式ランへ複製して移行する
- `GET /api/data` … 現在のデータを返す
- `PUT /api/data` … 全置換で保存（トランザクション）
- 4タブ: 帳票／型式ラン／法規DB／認可書実績

## ダミーデータについて

画面初期表示のSEEDデータ（型式ID・法規ID・認可書番号など）はすべて `DEMO-` 等の架空の識別子です。実在の型式・法規・認可書とは無関係です。型式↔法規↔認可書実績の対応関係（参照整合性）は、機能確認ができるように維持しています。

## 検証ハーネス（保存保護）

`verify/save-guard.html` に、保存保護の動作を確認する検証ページがあります。実際の `IListApp` コンポーネントをマウントし、`window.fetch` をモックして「初回読込が成功しない限り保存（PUT）が発生しない」ことなどを実測します。

**`npm run dev` は使わないでください。** `npm run dev` はAPIサーバも起動し、既存DB（`data/ilist.db`）を開いてしまいます。この検証に実APIも実DBも不要なので、Viteだけを単独で起動します。

```bash
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173 --strictPort
# ブラウザで http://127.0.0.1:5173/verify/save-guard.html を開き「すべての検証を実行」を押す
```

`--strictPort` を付けているので、5173が使用中なら黙って別ポートに移らず起動に失敗します。その場合は先に起動しているプロセス（`npm run dev` や別のVite）を停止してから実行してください。

なお、この起動方法ではAPIサーバがないため、通常画面（`http://127.0.0.1:5173/`）は「初回読込に失敗（保存は行われません）」と表示されます。これは保存保護が働いている正常な状態です。

ダミーデータのみを使い、実APIサーバ・実DB（`data/ilist.db`）には接続しません。テスト用の依存パッケージは追加していません。本番ビルド（`dist/`）にも含まれません。

## 現時点の制限・未実装（既知）

- **⑤-0は未着手**です。
- **Excel（指定装置一覧）取り込みは未実装**です。現行ソースにも実装がなく、今回の移植でも追加していません。

- （2026-09-06 対応済み）サーバへの初回接続に失敗した場合、読込成功として扱わないようにし、保存済みデータを自動保存で上書きしないよう修正しました。通信失敗・HTTPエラー・JSONとして解釈できない応答・データ形が不正な応答（`cert` が配列など）はすべて読込失敗として扱い、初回読込が成功するまで保存（PUT）を行いません（`src/IListApp.jsx` の起動時 `useEffect` と `isValidData` 参照）。保存状態の表示も「初回読込に失敗（保存は行われません）」と「保存に失敗（変更は未保存です）」を区別します。詳細と検証結果は [docs/current-task-legacy-2026-09.md](docs/current-task-legacy-2026-09.md) の追記を参照。
- 読込失敗後にサーバが復旧しても**自動では再読込しません**。画面をリロードする必要があります（再試行機能は未実装）。
- （2026-09-06 対応済み）保存要求が前後した場合に、古い保存応答が最新の編集の保存表示を上書きしないようにしました（編集世代による判定）。世代は**データ変更を受け付けた時点**（`setRuns`/`setRegs`/`setCert`）で進めます。保存`useEffect`の中だけで進めていた当初の実装では、変更受付からEffect実行までの間に届いた古い応答が最新扱いされる窓が残っていたため、これを塞いだものです（JSON読込経路で再現・修正を確認済み）。**いずれも画面表示の整合性のための対応で、サーバ側の書込順序の競合そのものを解決するものではありません。**
- プロジェクトグループ・認可継承の実装はありません。
