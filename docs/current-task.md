## 目的

初期ダミー（SEED）に「過去に法規不適合」の表示例を戻す。家庭側で目視確認できる場は初期ダミーしかないため、この表示例は必要。

本質の問題は、規則変更で表示例が消えても検出されないこと。初期データが取り得る判定状態の網羅を自動テストで守る。

F-20のSEED配分見直しとまとめて扱い、SEEDを2回作り直さない。型式ランは計10本、うちdrop済みは3本とする。

観測した事実：F-23の前例規則を適用すると、初期データで開いたときr5×REG-Bは、同じLOの比較元r4が同じ法規行に番号を持つため認可番号待ちになる。これはF-23のA2・A7どおりで判定の誤りではない。影響は初期ダミーで確認できる表示例だけ。F-23ではSEEDを変更していない。

## 対象範囲

- 単体HTML版の初期ダミー（SEED）の型式ランと、その日付・配分
- 判定関数が返し得る状態の列挙と、その網羅を確認する自動テスト
- SEEDの構成を固定している既存テストの期待値（完成条件7の範囲に限る）

## 完成条件

1. 初期データで開くと「過去に法規不適合」のセルが1つ以上出る。このセルは現行の判定規則（F-23を含む）をそのまま通した結果である。
2. 既存のrun.key（r1〜r7）は振り直さず、追加分はr8〜r10とする。r4→r5の比較元関係を維持し、F-23で意図した「比較元に番号があるので認可番号待ち」の例（r5×REG-B相当）が初期データに残る。日付・配分の調整は既存ランの値を変えて行ってよい。
3. 判定関数が返し得る状態すべて（判定不能・drop未定を含む）を、コード側の定義から列挙する。各状態が初期データに1件以上あることを自動テストで確認し、どれかが0件になったとき、または定義に状態が増えて初期データに無いときにテストが落ちる。
4. 型式ランは計10本。うちdrop済み3本、LO空1本、残り6本は現在LO〜将来LO（drop未定を含む）。
5. 判定ロジックと保存形式は変えない。既存の保存HTML／JSONを読み込んだときの判定結果は変更前と同じ。
6. ダミーは完全ダミーにする。実在の車名・型式・プロジェクトコード・認可番号は使わず、コードと車名を併記しない。
7. 判定ロジックを確かめるテストは、期待値を変えずにPASSする。SEEDの構成（本数・配分・特定セルの状態）を固定している期待値だけは、新しいSEEDに合わせて更新してよい。更新した箇所は、変更前後の値とあわせて報告に列挙する。
8. 報告には、変更前後の「状態×件数」表と、条件1・2のセルの座標（run.key×rid）を含める。
