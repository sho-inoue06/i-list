## 追記：2026-09-06 保存保護の実装・検証

### 目的
「初回データ読込に失敗しても、保存済みデータを上書きしないこと」の実装・検証のみ。機能追加はしない。

### 対象・正本
Notion本体には本セッションから接続できなかったため、ユーザー依頼文（2026-09-06付）を実行用抜粋として使用した。Notionを読んだとは報告しない。

### 原因（現行コードで確認）
- [src/IListApp.jsx](../src/IListApp.jsx) の初回読込 `useEffect`（修正前）は `fetch("/api/data")` が失敗した `catch` 節でも `setLoaded(true)` を呼んでいた。
- 自動保存 `useEffect` は `loaded` のみを条件にPUTを行うため、読込失敗直後でも800ms後にその時点のstate（多くの場合SEED）をPUTしてしまう。
- 復旧タイミングによっては、保存待ち（800ms）の間にAPIが復旧し、保存済みサーバデータがSEED等で全置換されうる。

### 修正内容
- `loaded` を「初回読込が成功した場合のみtrue」にするフラグに変更。通信失敗・`!r.ok`・応答形式不正（`runs`/`regs`/`cert`の型不一致）はすべて失敗として扱い、`loaded`をtrueにしない。
- 失敗時は `save` を `"error"` にするのみで、`loaded`はfalseのまま維持。自動保存 `useEffect` は `loaded=false` の間は何もしない（既存のガード `if (!loaded) return;` がそのまま機能する）。
- 初回読込useEffectに `cancelled` フラグを追加し、アンマウント後の状態更新を防止。
- `SaveStatus` 表示を `loading`（読込中）/`saving`/`saved`/`error`（初回読込に失敗（保存は行われません））に整理し、失敗時に「保存済み」と誤表示しないようにした。
- 変更ファイル: [src/IListApp.jsx](../src/IListApp.jsx) のみ。

### 実行コマンドと結果
- `npm run build` … 成功（`vite build`、1500 modules transformed、`dist/`生成）。修正前・修正後の両方で実行し成功を確認。

### 指摘2：読込失敗と保存失敗の表示を分離（修正済み）

- **限界**：その経路では世代判定でも弾けるため、**`dropped` 単独の効果は示せない**。

**案C：現状維持（Mを削除または「観測不能」と明記して残す）**

- **限界**：アンマウント後の挙動は未検証のまま残る。

### データ契約（追加分）
既存の `{ runs, regs, cert }` は変更せず、第4の領域 `decisions` を**配列**で追加した。
`run.key` は外部JSON経由では任意文字列を取りうるため、連結キーは作らず `runKey` と `rid` を別フィールドに持つ。

```
decisions: [
  { runKey, rid,
    state: "未確認" | "対象" | "対象外",
    reason,                 // 対象外は空白のみ不可
    decidedAt,              // 対象／対象外を明示確定した端末時刻。未確認は ""
    needsRecheck,           // 要再確認フラグ（立てるだけ・人の明示再確定でのみ解除）
    cond }                  // 確定時条件。未確認は null
]
cond = { typeId, sk, lo, drop, regId, shin, kei, parent, parentLink, parentRid }
  parentLink … "none"（親指定なし）/ "one"（完全一致が1件）/ "unresolved"（一致なし）/ "ambiguous"（複数一致）
  parentRid  … parentLink="one" のときだけ `g<数字>`。それ以外は ""（任意の親を選んで確定扱いにしない）
```

読込規則：
- `decisions` キーが**丸ごと無い**旧JSONは受理し**全件未確認**（既存のrid補完経路は従来どおり）。
- `decisions` が**ある**JSONでは `regs` 全行に `rid` が必要。欠けていれば**補番せずファイル全体を拒否**（補番でつなぎ直すと判断が別行へ誤結合するため）。
- 型不正・孤立参照・(runKey,rid)重複・不正state・対象外の理由欠落・cond不正は、**現在データを一切置換せず**理由を表示して拒否。
- 書き出し時、情報を持たない未確認レコード（理由空・要再確認なし・cond無し）は落とす（レコード無し＝未確認と同義）。

### 要再確認の扱い
- 条件に含める：run の `typeId/sk/lo/drop`、reg の `id/shin/kei/parent` と**親の解決状態**。
- 含めない：`run.gen`・`reg.label`（表示名だけの変更）。
- **`reg.parent` は親の `reg.id` 文字列**を持つため、親を改名・削除すると子のリンクが黙って切れる（既存挙動）。`parentLink`/`parentRid` を条件に加えてこれを検知する。`reg.id` は重複しうるので**完全一致のみ**を親候補とし、未解決・複数候補は要再確認として可視化する。
- 掃き出しは**立てるだけで下ろさない**。条件を元に戻す・メモ編集・再読込では解除されず、セルの「この内容で再確定」でのみ解除する。
- 装備変更などアプリに入力していない条件は自動検知できない。画面に明記し、ランの見出しから手動で要再確認にできる。
