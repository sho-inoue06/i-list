# 出荷の手順

禁止と境界は [AGENTS.md](../../AGENTS.md) に従う。このファイルは手順だけを持ち、AGENTS.md の境界を緩めない。矛盾したら AGENTS.md を優先して停止する。

実装セッションが、最終停止の後に祥の出荷承認を得た場合だけ実行する。

## 前提確認

1つでも満たさなければ、何もせず停止して報告する。

1. 祥の出荷承認がある（最終停止の報告に対して「出荷」と明示されている）
2. 現在のbranchが作業branch（Fでは docs/current-run.md のTaskに対応するbranch、chore・docsでは依頼文で指定されたbranch）で、承認時に報告したHEADと現在のHEADが一致する
3. 未コミット差分が無い
4. `gh` が使え、認証済み（`gh auth status`）。使えなければ停止して祥に返す

## 手順

1. `git push -u origin <branch>`
2. `gh pr create --base main --head <branch>`（本文は最後の停止報告を、implement.md の最終報告の形式のまま載せる。要約しない）
3. PRが mergeable で、base が main、head の SHA が承認時のHEADと一致することを確認する。コンフリクト・base違い・SHA不一致のどれかがあれば、マージせず停止する。続けて、PRのチェックを次のとおり確かめる。手順4へ進むのは、下の「すべて成功」のときだけ
   - 待つ：PRのチェック（`gh pr checks <PR番号>`）が1件以上あり、すべて終わるまで待つ。待つのは手順1の push から最長20分（`gh pr checks <PR番号> --watch` などで待ち、経過時間を自分で測る）
   - すべて成功：チェックが1件以上あり、すべて終わっていて、すべて成功している
   - 0件・時間切れ：20分待ってもチェックが1件も無い、または20分でまだ終わっていないチェックがあるときは、マージせず停止する（再実行はしない）
   - 失敗：終わったチェックに1件でも失敗（成功以外で終わったもの）があれば、1回目の失敗の内容（失敗したrunのURL・止まったステップの名前・`gh run view <run-id> --log-failed` の最後の出力）を控えたうえで、失敗したジョブを1回だけ再実行してよい（`gh run rerun <run-id> --failed`）。再実行は出荷を通じて1回だけ。再実行しないときは、マージせず停止する
   - 再実行の後：再実行の開始から最長20分待つ。すべて成功なら手順4へ進む。再実行も失敗、または20分で終わらなければ、マージせず停止する（2回目の再実行はしない）
4. `gh pr merge --squash --delete-branch --match-head-commit <承認時のHEAD>`（確認後にheadが動いていたらマージされない。失敗したら停止する）
5. `git switch main` → `git pull --ff-only origin main`。ff-onlyで失敗したら停止する（競合は解消しない）
6. マージcommitのhash、PR番号、ローカルmainのHEADを報告する。あわせてCIについて次を書く（手順3で停止したときも、その時点までを書く）
   - CI の run の URL、待った時間、成否、再実行の有無
   - ログに `npm run verify` の合計の行（`合計:` で始まる行）があればその行を、無ければ止まったステップの名前とそのステップの最後の出力
   - 再実行したときは、再実行したことと、1回目の失敗の内容（手順3で控えたもの）を必ず書く
