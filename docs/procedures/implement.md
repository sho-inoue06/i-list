# 実装セッションの手順

禁止と境界は [AGENTS.md](../../AGENTS.md) に従う。このファイルは手順だけを持ち、AGENTS.md の境界を緩めない。矛盾したら AGENTS.md を優先して停止する。

## standard

実装 → セルフ検証 → レビュー → 指摘修正1回 → 再検証 → 停止（祥が完成版を確認）→ 出荷承認 → [docs/procedures/ship.md](ship.md)

- `docs/current-run.md` で実装するFの既定。
- レビューは [docs/procedures/review.md](review.md) に従い、`docs/current-run.md` のReviewer・Reviewer model・Reviewer effort で起動する。
- 停止はレビューと修正の後の1回。push・PR作成・マージは、停止後の祥の出荷承認を得てから ship.md の手順でだけ行う。

## exploration

試作 → セルフ検証 → 停止

- 祥がexplorationと明示したときだけ使う。
- レビュー・commit・pushなし。
- 採否後に正式なFを切り直す。

## セッション運用

- 着手時に、現在のbranch、HEAD、未コミット差分、mainとの差を確認する。
- standardは出荷（ship.md）の完了で、explorationは停止でセッションを終了する。手順にない追加作業を推測して実行しない。
- 自分が書いたコードの不具合修正は同一成果単位なので、同じセッションで行う。
- 完成条件や前提の変更が必要になった場合は、現在のセッションを停止して報告する。祥がNotionの完成条件を直し、作業branchを消して /prepare-f からやり直す。branchの削除は祥が行い、実装AIは行わない。

## 見つけたもの
新しい問題を見つけたら、現在の範囲へ勝手に追加せず、現在のFとの関係で次のどれかに振り分ける。

- 現在の完成条件に必要：条件番号または再現手順を付けて、現在のFの中で扱う。
- AGENTS.md の停止条件（前提崩れ・安全性・データ破壊・情報持ち出し・権限の疑い）に当たるもの：AGENTS.md に従い停止して報告する。
- 独立して価値がある別案件：現在のFを止めず報告する。停止の報告で下のブロックを1案件1つ、F番号・優先順位・完成条件・解決策は決めず、解決策ではなく「〜のとき、〜になる」と観測事実で書く。既存バックログへの追記か新規候補かはAI1が重複確認して判断する。件数の上限と、F完了までDefineしないことは AGENTS.md に従う。
- 感想、命名、整形、細かい性能改善：バックログ候補にせず、最終報告に残すだけにする。

```
[NOTION_BACKLOG_CANDIDATE]
発見元：F-xx
作業名：
観測した事実：
再現手順・関連する完成条件：
影響範囲：
現在のFを止めるか：はい／いいえ（理由）
既に決まったこと：
未決事項：
[/NOTION_BACKLOG_CANDIDATE]
```

## 最終報告の形式
standardではレビュー・修正・再検証の結果を、explorationではレビュー・commit・pushを行わないことを報告する。push以降は、祥の出荷承認の後に ship.md の手順でだけ行う。
- 最終報告は最後の停止点で出す報告で、それ単体で経緯と結果が分かる自己完結した内容にする。出荷時にPR本文としてそのまま残り、AI1はPRから読む。途中報告をNotion向けに別途作らない。

0. 引き渡し情報：成果番号、branch、HEAD、push先
1. 変更したもの
2. 完成条件ごとの確認状況
3. 実行した検証と結果
4. 未検証事項
5. レビュー
6. 見つけたもの
7. 安全性チェック：ダミーのみ／秘密情報なし／依存・権限の無断変更なし／外部公開なし／既存データ破壊なし／範囲外ファイル変更なし を各1行で確認
8. 祥が次に行う操作（出荷承認を求める。承認時に報告したHEADを0に明記する）
9. 祥またはAI1に判断してほしいこと
