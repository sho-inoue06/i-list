# 事前点検の手順

禁止と境界は [AGENTS.md](../../AGENTS.md) に従う。このファイルは手順だけを持ち、AGENTS.md の境界を緩めない。矛盾したら AGENTS.md を優先して停止する。

## 目的

凍結前の `docs/current-task.md` が、境界データでも判定でき、否定条件を持ち、既存の挙動と矛盾しないかを見る。chore・docs の依頼文を入力とする場合も、同じ観点で見る。

業務上の意味の正しさは見ない（祥が停止で見る）。

## 起動

準備セッションが [.claude/skills/prepare-f/SKILL.md](../../.claude/skills/prepare-f/SKILL.md) の手順で起動するか、祥が指示したときに行う。2ファイルの生成の後、凍結commitの前に行う。

chore・docs の場合は、作業セッションが着手前（branchを作った後、ファイルを変える前）に、[docs/codex-review.md](../codex-review.md) の起動コマンドで起動する。依頼文の全文を1字も変えずに、次の固定の1文の後ろに付けて渡す。固定の1文以外を足さない。

「AGENTS.md と docs/procedures/precheck.md に従って、下の依頼文を事前点検して。今回は docs/current-task.md の代わりに、下の依頼文を入力とする。」

## 入力

- `docs/current-task.md`（未commit）
- repoの現物（コード・完了済みFの挙動）
- chore・docs の場合：`docs/current-task.md` の代わりに、固定の1文の後ろに付けた依頼文の全文。依頼文の「完成条件」「出てはいけないもの」「やらないこと」「必須検証」を、current-task.md の同名の節として読む。

## 禁止

- ファイル変更
- Git変更
- Notionの読み書き

## 観点

0. 本数：A（出るもの）が8本を超えていたら、観点1〜5を点検せず「分割」で差し戻す。
1. 判定可能性：条件ごとに、境界データ（LO空・drop空・新規ラン・法規0件・前例なし）で○×が決まるか。
2. 否定条件：「出てはいけないもの」が番号付きであり、主要な出力に対応しているか。
3. 整合：条件同士／既存コードの挙動／やらないこと と矛盾しないか。根拠はファイルと行で示す。
   - 条件が既存の画面の表示（印・色・文言）に触れるときは、区分・状態ごと（例：危険一覧の期限超過／期限前・未取得／黄色予告）に既存の表示規則が違わないかを照合する。条件が全区分に同じ印を求め、既存の規則が区分によって出し分けているなら、観点3のNGとする（F-42のA4で、期限超過の行に計画済みを出さない規則を見落としたため）。
   - 条件が変える・足す・消す用語、番号（観点番号・条件番号など）、ファイル名、見出しを点検役が自分で選び、repo 全体（.git・node_modules を除く）を grep する。同じことを書いている他の箇所が、完成条件か「やらないこと」に入っているかを見る。どちらにも入っていなければ観点3のNGとし、根拠に grep で当たったファイル:行を書く。参照専用の旧ファイル（docs/current-task-legacy-2026-09.md、docs/current-task-history-2026-09.md）だけに当たったものはNGにしない。
4. 範囲：完成条件が区別する場合（例：結果の種類 PASS／FAIL／SKIP／ERROR／時間切れ、入力の種類、データの区分・前例の有無）ごとに、必須検証が1件以上試すか。試さない場合があるなら、それを未検証として報告させているか。どちらでもなければNGとする。
5. 外したものの出現：「やらないこと」や対象外で外したもの（ファイルの種類・区分・結果の種類など）が、入力や実行時に現れたときの扱い（止める／無視する／報告する等）が、条件で1つに決まっているか。根拠は観点3と同じく、ファイル:行で示す。

## 出力（固定）

1行目は AGENTS.md の「手順の索引」どおり「読んだ手順：docs/procedures/precheck.md（版：<版>）」とし、その後に次だけを書く。

```
判定：OK／NG
```

NGのときは、1件ずつ次を書く。

```
- 条件番号：
- 観点：0〜5のどれか
- 根拠：ファイル:行（current-task.md の該当行、矛盾する既存コード・既存の挙動の行。chore・docs では current-task.md の代わりに依頼文の該当の条件番号・見出し）
- 何が決まらないか：
```

- 観点0に当たった場合は、この1件だけを書く（条件番号：全体、何が決まらないか：分割）。
- 直し方は書かない。
- OKのときは判定だけを書く。
