# Workflow Profiles

1成果単位の回し方の型。今回どれを使うかは docs/current-run.md に記録する。
このファイルは AGENTS.md の安全境界を緩和しない。

## standard

実装 → セルフ検証 → レビュー → 指摘修正1回 → 再検証 → 停止①（完成版確認）→ push承認

- 完成条件が明確なF向け。既定値。
- 停止①はレビューと修正の後。

## visual-first

実装 → セルフ検証 → 停止①（方向性確認）→ レビュー → 指摘修正1回 → 再検証 → 停止②

- 画面・見せ方・却下可能性が高いF向け。
- 方向性が否定されたらレビューへ進まない。

## exploration

試作 → セルフ検証 → 停止①

- レビューと修正ループなし。
- commit・pushしない。採否決定後に正式なFを切り直す。

## 共通

- 実装者とレビュー者は別AI・別セッションとする。
- レビューは読み取り専用で行う。
- 指摘には完成条件番号または再現手順を付ける。
- 仕様変更が必要なら停止し、Notion更新 → current-task.md 再生成 → 新セッションで再開する。
